# 面试准备

## 材料

读：看板上这个岗位的记录（`timeline`、`next`）和 `docs/`（`jd`、`emails` 里的面试官和轮次、之前轮次的 `debrief-*`、`cover-letter`）；`criteria.md`（定位、竞争力、缺口）；简历；`private/question-bank.md`。

缺关键信息（面试官是谁、第几轮、什么形式）就先问用户。

## 调研（每一条都记来源链接）

### 1. 面试官（每人一节）

只查公开的职业信息：LinkedIn（通过搜索结果）、公司官网介绍、发表的文章和论文、演讲、播客、新闻采访、Google Scholar。

- 职业路径：现任职位、在公司多久、之前在哪、什么背景（业务 / 技术 / 学术 / 咨询）。
- 公开说过、写过、关心的主题。
- 在这次面试里的角色：未来的直属上级、同事、HR、上级的上级——各自会看重什么。
- 和用户的共同点（学校、行业、话题），能自然提起的。

不查、不写私人生活信息（家庭、住址、私人社交账号等）。查不到就写查不到，不要猜。同名的人要核对公司和职位，不确定就标明。

### 2. 公司

主营业务和收入来源；最近 6–12 个月的新闻（财报、战略、重组、裁员、并购、新产品、领导层变动）；在香港 / 新加坡 / 亚太的业务和定位；主要竞争对手。

### 3. 部门和团队

部门在公司里的位置、这个岗位汇报给谁、团队规模、同一个团队最近在招的其他岗位、这个岗位是新增还是替补（从 JD 的措辞和以往招聘记录判断）。

### 4. 推测业务需求

把 JD 和以上调研放在一起，推测这个人入职后 6–12 个月要解决的 3–5 个问题。每条写依据，标明「推测」。

## 预测问题

15–25 个，按类别：

1. 开场和动机：自我介绍、为什么是这家公司 / 这个岗位、为什么现在换工作。
2. 经历深挖：简历上和 JD 最相关的几段，面试官会追问的细节。
3. 专业能力：JD 的核心要求，结合面试官背景（比如研究出身的面试官会问方法论）。
4. 行为题：用 STAR 结构，从简历里挑合适的真实经历。
5. 针对能力缺口的质疑：`criteria.md` 里列的缺口，面试官大概率会问。
6. 情景题：基于推测的业务需求，比如「如果你来了，前 90 天做什么」。
7. 收尾：期望薪资（对照 `salary.md`）、最早入职时间、其他面试进程。

每个问题写：**为什么会问**（联系面试官背景或 JD）、**回答角度**、**要点**（3–4 条）、**可以用的经历**（只用简历里真实的）。

## 反问问题

8–10 个，按面试官分开：问未来上级的（团队目标、怎样算做得好、最大的挑战）、问同事的（日常工作、协作方式）、问 HR 的（流程、时间线）。问题要体现做过功课，也要帮用户判断这个岗位是否符合 `criteria.md`（比如居家办公、出差、团队稳定性）。

## 输出

写进看板这个岗位的 `docs/interview-prep-<轮次>`（例如 `interview-prep-1`），本地在 `private/applications/<文件夹>/` 存一份：

1. 一页速览：时间和形式、每位面试官一句话画像、这个岗位最需要的 3 件事、用户最该强调的 3 点、最要准备的 3 个风险问题
2. 面试官画像
3. 公司和部门
4. 推测的业务需求
5. 自我介绍（60–90 秒；默认英文，面试用别的语言就跟着换）
6. 预测问题和回答要点
7. 反问问题
8. 面试前检查清单（链接、设备、材料、时区）
9. 来源

在对话里先给一页速览，告诉用户完整版存在哪，然后问要不要模拟面试：你扮演面试官，一次问一个问题，用户答完你点评，再问下一个。
