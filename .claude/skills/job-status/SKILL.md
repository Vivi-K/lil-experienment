# 进程更新

## 1. 读邮件

提取：

- 发件人：姓名、职位、邮箱、所属公司（公司 HR 还是猎头）
- 类型：面试邀请 / 约时间 / 笔试或测评 / 补材料 / 拒信 / offer / 猎头主动联系 / 其他
- 岗位：公司、职位、岗位编号
- 时间：面试日期、时间和时区（换算成香港时间）、各种截止日期
- 面试：轮次、形式（视频 / 电话 / 现场 / 案例 / 演示）、时长、面试官姓名和职位、要准备什么
- 需要用户做的事

邮件里没有发件人信息就请用户补上（面试准备要用）。

## 2. 对上追踪表

- 按公司 + 职位在看板 `jobs` 里找（包括自动投递系统投的）。对不上，或者同一家公司有好几个岗位时，问用户。
- 找不到（比如猎头主动联系的新岗位）：问用户要不要加进来。要加的话，先按 `criteria.md` 过硬性条件、打分，把结果告诉用户。

## 3. 更新

- 看板：`status` / `stage`（例如 `interview` + 「一面」），`next` / `nextDate`（写具体时间，比如「10 月 3 日 14:00 一面（视频）」），`timeline` 追加一条（发件人和要点）。拒信、岗位关闭改成 `closed`，`stage` 写结果。
- 看板这个岗位的 `docs/emails`：追加这封邮件的全文（含发件人信息），面试准备要用。
- 提到了面试官的，在这一行里单独列出姓名和职位。

## 4. 告诉用户

- 一句话：状态改成了什么。
- 需要回复的：给回复草稿（确认时间、提问题等），语言和来信一致。
- 面试：提醒日期时间，建议现在就开始 `interview-prep`。
- 拒信：简短安慰；看看有没有规律（比如总卡在同一个缺口上），有的话问用户要不要更新 `criteria.md`。
- offer：列出要确认的条款，对照看板上这个岗位的 `docs/salary` 准备谈薪。

## 顺便检查

每次处理进度时看一眼看板：

- `applied` 状态投递超过 14 天没有更新的：列出来，附跟进邮件或 LinkedIn 消息草稿，由用户决定发不发。
- 超过 30 天没有消息的：问用户要不要改成 `closed`、`stage` 写「无回复」。
