# 制定 / 更新筛选标准

`criteria.md` 是之后所有检索和打分的核心。目标是精投，标准宁严勿松。

## 第一次制定

1. 准备
   - `job-search/private/` 不存在时，从 `job-search/templates/` 复制 `criteria.md` 过去，建好 `profile/`、`searches/`、`applications/`。
   - 读简历（`private/profile/`）。只有 PDF 或图片就先转成 `cv.md` 文字版，请用户核对。还没有简历就先请用户发过来。
2. 先给判断，再提问。读完简历后告诉用户：
   - 你认为最有竞争力的 3 点，每点附简历里的证据；
   - 看起来最适合的 2–3 个方向；
   - 明显的能力缺口。
   以此作为讨论的起点，请用户纠正。
3. 分 2–3 轮提问，每轮 4–6 个问题，后一轮根据前一轮的回答调整：
   - 方向：喜欢做的具体工作内容（请用户举过去真实做过的例子）、不喜欢做的、想转去的方向、不想再做的方向。
   - 硬性条件：城市、居家办公比例、职级 / 头衔、薪资下限（月薪还是年薪、币种、含不含奖金）、签证、出差、最早入职时间。
   - 排除：公司、行业、雇主类型，以及原因。
   - 能力缺口：用户自己觉得哪里不够，加上你从简历看出来的。
   - 加分项：公司规模、团队、国际化程度、学习机会等。
4. 讨论，而不只是记录
   - 回答之间有矛盾就指出来（比如薪资下限和目标职级对不上、方向太散）。
   - 用户犹豫时给出你的建议和理由，帮用户做决定。
   - 帮用户说清定位：一句话讲明白「我是谁、能解决什么问题、为什么是我」。
5. 写 `criteria.md`：每一节都填；还不确定的写「待确认」。写完把定位、硬性条件、排除清单、目标方向用简短列表发给用户确认。
6. 在「变更记录」里记下「初版」。

## 更新标准

触发：用户对推荐的岗位说了合适或不合适的原因，或者提供了新信息。

1. 改对应的那一节。如果是对某个岗位的反馈，在「从反馈中学到的」里加一行：岗位 → 反馈 → 由此形成的规则。
2. 规则要能直接用在下一次检索上：「不看 X 行业」比「这个不太好」有用。反馈含糊时追问一句为什么。
3. 新反馈和已有规则冲突时，先问用户以哪个为准。
4. 在「变更记录」里记一笔（日期、改了什么、原因），然后用一两句话告诉用户改了什么。
5. 反馈是针对看板上某个候选岗位说不投的，同时把看板上这条改成 `skipped`、写 `skipReason`，`timeline` 追加「已写入标准」。用户在看板上写的不投原因也按这条处理。
6. 定位、硬性条件、目标方向、排除清单有变化时，同步更新看板的 `meta/profile` 摘要（格式见 `job-search/board.md`）。
