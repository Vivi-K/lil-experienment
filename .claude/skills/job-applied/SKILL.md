# 投递归档

## 1. 确认是哪个岗位

在 `tracker.md` 的「候选」里找；找不到就请用户给链接或 JD。一次投了几个就逐个处理。

## 2. 文件夹

`private/applications/YYYY-MM-DD_公司_职位/`：日期是投递日期；公司和职位用英文短名，空格换成 `-`。之前写求职信或查薪资时已经建过就沿用。

## 3. 存 JD：`JD.md`

必须是**完整原文**，不能是摘要。

- 用户贴的原文最可靠，直接用。
- 否则用 WebFetch 打开链接，prompt 里写明「逐字返回完整的职位描述，包括公司介绍、职责、要求、福利、薪资，不要总结、不要省略」。看起来不完整就告诉用户，请用户复制原文贴过来。
- 打不开（被网络策略拦截、要登录、已下线）：先把能找到的信息存下来，标注「待补全」，再请用户贴原文。

格式：

```markdown
# <职位> — <公司>

| 项目 | 内容 |
|---|---|
| 链接 | |
| 地点 | |
| 岗位编号 | |
| 发布日期 | |
| JD 写明的薪资 | |
| 投递日期 | |
| 投递渠道 | 官网 / LinkedIn / 内推（谁）/ 猎头（谁） |
| 存档日期 | |
| 来源 | 用户粘贴 / 网页抓取 |

## 职位描述原文

（完整原文）
```

## 4. 更新追踪表

- 从「候选」移到「进行中」：状态「已投递」，填投递日期；下一步写「YYYY-MM-DD 还没消息就跟进」（投递日 + 14 天）；文件夹写相对路径。
- 匹配度、前景沿用检索时的分数。用户自己找的岗位现在按 `criteria.md` 打分。

## 5. 时间线：`timeline.md`

```markdown
# 时间线 — <公司> <职位>

| 日期 | 事件 | 细节 |
|---|---|---|
| YYYY-MM-DD | 已投递 | 渠道；附了 / 没附求职信 |

## 邮件原文
```

## 6. 告诉用户

一两句话：存在哪、JD 是否完整、哪天提醒跟进。
