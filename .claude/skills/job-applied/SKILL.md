# 投递归档

看板的读写方法和字段见 `job-search/board.md`。

## 1. 确认是哪个岗位

在看板 `jobs` 里按公司 + 职位找；找不到就请用户给链接或 JD，按 `board.md` 的 id 规则新建一条（这时按 `criteria.md` 打分）。一次投了几个就逐个处理。

## 2. 存 JD：看板 `docs/jd`

必须是**完整原文**，不能是摘要。

- 用户贴的原文最可靠，直接用。
- 否则用 WebFetch 打开链接，prompt 里写明「逐字返回完整的职位描述，包括公司介绍、职责、要求、福利、薪资，不要总结、不要省略」。看起来不完整就告诉用户，请用户复制原文贴过来。
- 打不开（被网络策略拦截、要登录、已下线）：先把能找到的信息存下来，标题里加「待补全」，再请用户贴原文。

写成 `{title: "JD 全文", markdown, updated}`，`markdown` 的格式：

```markdown
# <职位> — <公司>

| 项目 | 内容 |
|---|---|
| 链接 | |
| 地点 | |
| 岗位编号 | |
| 发布日期 | |
| JD 写明的薪资 | |
| 投递日期 | |
| 投递渠道 | 官网 / LinkedIn / 内推（谁）/ 猎头（谁） |
| 存档日期 | |
| 来源 | 用户粘贴 / 网页抓取 |

## 职位描述原文

（完整原文）
```

本地在 `private/applications/YYYY-MM-DD_公司_职位/JD.md` 存一份（日期是投递日期；公司和职位用英文短名，空格换成 `-`）。

## 3. 更新看板上的这条

- `status: applied`，`applied` 填投递日期，`jdStatus` 写「JD 已存档」或「JD 待补全」。
- `next: "还没消息就跟进"`，`nextDate` = 投递日 + 14 天。
- `timeline` 追加：`{date: 投递日期, text: "已投递（渠道；附了 / 没附求职信）"}`。
- 带上读到的 `if_version`，看板上用户改过的字段不要覆盖。

## 4. 告诉用户

一两句话：看板已更新、JD 是否完整、哪天提醒跟进。
