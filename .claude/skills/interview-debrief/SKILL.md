# 面试复盘

## 1. 收集

先让用户随便说，越细越好。说完后对照下面的清单，把没提到的一次问完，不要一个一个挤牙膏：

- 面试官是谁（和计划的一样吗）、多长时间、什么形式
- 问了哪些问题，用户怎么答的
- 对方透露的信息：团队、岗位的真实工作内容、汇报关系、挑战、薪资、流程、时间线、还有几轮
- 对方的反应：追问多的地方、表现出兴趣或迟疑的地方
- 用户自己的感受：哪里答得好、哪里卡住、对这个岗位的兴趣是变高还是变低

## 2. 记录：`debrief-<轮次>.md`

写进看板这个岗位的 `docs/debrief-<轮次>`，本地在 `private/applications/<文件夹>/` 存一份：

1. 基本信息：日期、轮次、面试官、形式、时长
2. 对方透露的信息，和 JD、面试准备里的推测对比：哪些被证实了、哪些不一样
3. 逐题：问题 → 用户的回答要点 → 评价（好在哪、缺什么）→ 更好的答法
4. 信号：积极的 / 要留意的
5. 评估：通过可能性（高 / 中 / 低，附理由）；这个岗位是否仍然符合 `criteria.md`，有没有新发现的红旗
6. 下一轮要准备什么

## 3. 更新其他文件

- 看板：`stage`（例如「一面已完成，等结果」）、`next` / `nextDate`（对方说的反馈时间再加几天缓冲，到时没消息就跟进），`timeline` 追加一条。
- `private/question-bank.md`：把这次被问到的问题加进去，按类别，注明公司、轮次、日期。文件不存在就新建。
- 面试中得到的新认识（比如发现某类工作其实不喜欢、某个缺口被反复追问）：问用户要不要写进 `criteria.md`，同意就用 `job-criteria` 更新。
- 如果对岗位的判断变了，修正匹配度 / 前景分数，说明原因。

## 4. 给用户

- 简短复盘：做得好的 3 点、可以改进的 3 点、通过可能性。
- 感谢信草稿（面试后 24 小时内发）：每位面试官一封，提到面试里聊到的一个具体话题；由用户决定是否发送。
- 有下一轮的话：下一轮大概会考什么、要准备什么。
