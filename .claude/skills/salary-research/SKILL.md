# 薪资期望

## 调研

1. 先看 JD 和招聘页有没有写薪资范围——有的话这是最强的依据。
2. 用 WebSearch 查，至少 3 个不同来源，记下来源、年份、数值：
   - 猎头的年度薪资报告（当年或上一年）：Michael Page、Hays、Robert Walters、Morgan McKinley、Randstad 等的香港 / 新加坡 salary guide。
   - 薪资网站：Glassdoor、Indeed、Payscale、Levels.fyi（科技公司）、JobsDB；新加坡可以看 MyCareersFuture 上同类岗位公开的范围。
   - 这家公司的同类岗位，以及同行业相近的头衔。
3. 统一口径再比较：月薪还是年薪、币种、base 还是总包（香港常见 13 薪 + 奖金，新加坡常见 AWS 第 13 个月 + 奖金）、职级是否对应。
4. 对照 `criteria.md` 里的薪资下限和目标职级。

## 输出

写进看板这个岗位的 `docs/salary`（`{title: "薪资调研", markdown, updated}`），并把建议数字写到岗位的 `salary` 字段；本地在 `private/applications/<文件夹>/salary.md` 存一份。在对话里给：

1. 市场范围表：

   | 来源 | 头衔 / 职级 | 数值（原口径） | 折算成月 base | 年份 | 链接 |
   |---|---|---|---|---|---|

2. 判断：这家公司在市场里偏高还是偏低、这个岗位大致对应什么职级、用户的条件在范围里处于什么位置。
3. **建议填写的数字**
   - 表单只能填一个数：给一个具体数字（月 base，写明币种），通常在市场 P50–P75 之间，且不低于用户的下限。
   - 可以填范围：给一个范围，范围的下限就是用户能接受的数。
4. **口头回答**：英文、中文各一段。先说看重整体 package 和岗位职责，再给数字。
5. 谈判提示：可以争取的部分（base、奖金、签约金、假期、居家办公、职级），以及在哪个阶段提。
6. 数据少或者来源旧的话，直接说置信度低。

不建议用户主动透露现在的薪资，除非用户自己想这样做；对方追问时，给一个得体的回答。
